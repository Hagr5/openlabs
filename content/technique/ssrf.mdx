## Overview

SSRF happens when a server-side feature fetches a URL that you supply, and that server has network access you don't. Point it at an internal hostname or port and the response comes back through the feature that was only meant to fetch public resources.

## Examples

Watch for any field that fetches a resource by URL: image imports, webhook URLs, PDF generators, link previews. Try internal hostnames, `localhost`, alternate ports, and cloud metadata addresses. Compare response timing and content for signs the request actually reached an internal target.

## FAQ

**Is SSRF only useful for reading internal web pages?**

No. It's often a stepping stone — reaching an internal API, metadata endpoint, or service that then exposes a further flaw.

**Do I need special tooling?**
