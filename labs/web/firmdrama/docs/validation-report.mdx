## What the ingress check proves

| Current test | Behavior checked |
| :--- | :--- |
| `test_upstream_idle_close_reaches_client_and_releases_slot` | Upstream closure reaches the client and frees the admitted connection slot |
| `test_client_close_reaches_upstream` | Client closure reaches the upstream socket |
| `test_live_connection_preserves_multiple_large_responses` | Multiple large responses arrive intact on a live connection |
| `test_half_closed_client_receives_delayed_response` | Client write-side EOF still permits a complete delayed response |
| `test_stalled_write_times_out` | A stalled drain is bounded by the idle timeout |
| `test_stalled_close_aborts_transport` | A stalled writer close aborts its transport after the close timeout |

Four tests exercise real loopback sockets with a controlled test upstream; two
use controlled writer mocks for deterministic timeout checks.
They do not exercise the application, its challenge path, a real browser's
idle/retry behavior, TLS, saturation, every timeout, or every write failure.

The ingress handler preserves a bounded response after client write-side EOF.
Response completion or failure cancels and awaits remaining forwarding work,
closes both writers with a deadline, and releases the slot. The older three-case
results remain dated historical evidence; the current suite contains six cases.
