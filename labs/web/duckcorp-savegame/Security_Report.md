DuckCorp Internal Network Assessment - Security Report9.1 Executive SummaryThe "DuckCorp SaveGame Manager" challenge demonstrates a critical vulnerability chain involving Server-Side Request Forgery (SSRF) and a backend parsing discrepancy. The application allows users to import gaming profiles via a URL. Due to a flaw in how Python 3 handles the filter() function and a discrepancy between urllib.parse and pycurl URL parsing, an attacker can bypass protocol and domain restrictions. This allows the attacker to send a malicious gopher:// payload to the internal uWSGI socket (port 5000), achieving Remote Code Execution (RCE) to extract the highly restricted system flag.  9.4 Attacker Starting PointInitial Access: The attacker starts as a normal employee (Intern) with the profile ID muhammadibn3bdullah.Privileges: Low-level access; can view their own profile and use the "Profile Importer" feature.Knowledge: The attacker knows the application takes external URLs to import JSON data.9.5 Attack SurfaceThe primary attack surface is the /profiles/import endpoint defined in routes.py, which accepts a JSON payload containing a profileURL parameter. This parameter is processed by the get_profile(url) function in util.py.  9.6 Vulnerability Description & Root CauseThe vulnerability stems from two distinct logical flaws in util.py:  Protocol Restriction Bypass (Python 3 filter flaw):
The application attempts to restrict the scheme to http or https using:
if not filter(lambda x: scheme in x, ('http',' https')):.
Root Cause: In Python 3, filter() returns an iterator object, which always evaluates to True in a boolean context, regardless of its contents. Therefore, not filter(...) evaluates to False. The scheme validation never triggers, allowing protocols like gopher://.  Domain Restriction Bypass (Parser Discrepancy):
The application enforces the domain using:
elif domain and not domain == 'duckcorp.local':.
Root Cause: There is a parsing discrepancy between urllib.parse.urlparse and the pycurl library. If an attacker crafts a URL like gopher://127.0.0.1:5000\@duckcorp.local/_payload, urlparse identifies the hostname as duckcorp.local (passing the check), whereas pycurl processes the actual connection to 127.0.0.1 on port 5000.  9.7 Intended Attack PathA competent participant should follow these steps to retrieve the flag:Step 1: Reconnaissance & Bypassing RestrictionsThe attacker attempts to use the /profiles/import endpoint. They discover that providing internal IPs is blocked by the domain check. By experimenting with URL formatting, they find that gopher://127.0.0.1:5000\@duckcorp.local/ bypasses both the protocol and domain filters.Step 2: Crafting the uWSGI Payload
Knowing the application runs on uWSGI via port 5000 (standard configuration for Python web apps in CTFs), the attacker uses a tool like Gopherus to generate a uWSGI payload.
The payload is designed to execute a Python command that runs the SUID binary /readflag and writes its output to a publicly accessible directory:
os.system('/readflag > /app/application/static/images/flag.txt').  Step 3: Executing the SSRFThe attacker sends the following POST request to the application:HTTPPOST /profiles/import HTTP/1.1
